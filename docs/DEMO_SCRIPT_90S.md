# 90-Second Portfolio Demo Script

## 0–15s — Problem and boundary

“CarbonFactorResolver accepts a structured factor query. It does not parse PDFs or calculate a
complete footprint. Its job is to retrieve traceable factor records and then enforce units,
lifecycle boundary, subject compatibility and provenance before a human locks a choice.”

## 15–40s — Normal multilingual hit

Submit the synthetic query `月岭氧化铝粉`, `2 kg`, `raw_material`, `powder`.

Show Trace resolving the bilingual alias to the alumina entity, retrieving
`R2-MOON-ALUMINA`, passing qualification and returning it as Top-1. Point out the synthetic
source locator and evidence hash.

## 40–62s — Unit qualification

Submit `moonridge alumina powder`, `0.5 t`. Show the effective target unit and the same source
record passing a same-dimension mass conversion. Explain that values are never generated by an
LLM and cross-dimension conversions fail closed.

## 62–82s — Safe `MORE_INPUT`

Submit `metallic aluminium feedstock` without a production route. Show that CFR identifies
aluminium but does not choose primary versus secondary production. It returns
`MORE_INPUT_NEEDED` and the smallest route question instead of forcing a factor.

## 82–90s — Honest evaluation

“The closed Portfolio Benchmark is 39/40, but the independent rc.2 sealed run missed its Top-1
gate at 83.33%. I preserved that failure and marked the release NO-GO. The project demonstrates
retrieval engineering, deterministic safety, evaluation discipline and honest release gates—not
a production carbon-accounting claim.”
