GRAPHSTATE · READ / WRITE CONTRACT

三、关键 State 分组

GraphState 是所有 Node 的共享、显式载体。展开面板可查看主要字段、写入 Node 与后续消费者。

1. Request / Identity State
request → normalized → material_identity
  • Validate 后先生成 MaterialMention、IdentityResolution 与 RetrievalIntent，再允许 Local Retrieval。
  • 语义注册表写入 registry version、Material/Process/Form rule IDs 与 relation IDs。
  • 未知材料的 LLM 建议只能进入 registry_suggestion=DRAFT，不能激活规则或产生因子。
  • 同时计算 raw fingerprint 与 normalized business fingerprint。
2. Request Gap / More-input State
request_gaps · required_fields · provisional_options · request_resolution_plan
  • 宽泛产品族不能静默选择某个子类型。
  • 存在必填身份缺口时清空可决策候选，但保留 recall 与 qualification 证据。
  • 最终由 Top-K 统一返回 MORE_INPUT_NEEDED。
3. Retrieval / Qualification State
local_records · link_attempts · recall_observations · qualifications · excluded_candidates
  • 检索顺序：Exact → registered Alias → identity-aware Related。
  • Direct、Proxy、Grade Anchor 共用 Qualification Policy。
  • 排放限值、错误指标、边界或产品限定不能进入正常 A1 Candidate Pool。
  • Trace 同时锚定正式数据库 catalog version 与 SHA-256。
4. Gap / Plan State
resolution_candidates · gaps[candidate_id] · resolution_plans[candidate_id]
  • Gap 类型：Unit、Reference Flow、Process、Grade/Composition、Material Absent、Boundary、Geography、Time、Form。
  • Planner 只建立有限步骤和依赖，不执行数值计算。
  • Material Class 仍未参与前置路由。
5. Evidence / Derivation State
reference_flow_records · parameter_evidence · accounting_assignments · transformation_steps · derived_candidates
  • 每个数值变换保留 formula ID、输入、输出、source IDs 和 parameter IDs。
  • 过程计算验证共同上游非负、能源份额闭合、includes_process 与参数作用域。
  • 附加过程排放必须参考侧和目标侧同时有记录，数字 0 是证据，记录缺失不是零。
  • 成品、购入耗材 A1 与现场直接排放 A3 是三个独立 subject；电极可为 IDENTIFIED_NOT_QUANTIFIED，并列出缺失用量和上游因子。
  • “氧化铝”等化学实体名不会触发 A3；只有显式 use_context 或受控目标工艺证据可触发现场氧化/燃烧/反应。
  • 派生因子改变时按规范化数量重算总排放；锁定前再次校验一致性。
  • 牌号只接受同 series 且资格完整的锚点；禁止按纯度比例缩放整个因子。
6. Late Proxy State
material_class · proxy_records · proxy_candidates
  • 守卫：无可解析本地候选，或候选仍有 MATERIAL_ABSENT。
  • Material Class 仅指导最后的技术代理，不抢占目标材料本身的检索。
  • Proxy 也必须资格评估，并只允许一次候选级有限解析。
7. Pool / Ranking / Output State
candidate_pool · ranked_candidates · recommendation · reviewable_candidates · diagnostic_candidates
  • 按 Candidate ID 合并场景，不按 source ID 粗暴去重。
  • 排序键：Resolution Type → 受审来源优先级 → Strength → Score → Evidence Coverage → Assumptions → Stable Lineage。
  • 显式来源优先级只接受 0–1000 的真正整数；bool、float、字符串和越界值逐记录回退并写入质量告警。
  • 输出严格分层：candidates 可审批，reviewable_candidates 需 Override，diagnostic_candidates 不可审批。
8. Trace / Diagnostics State
events · trace · assumptions · warnings · errors
  • 每个 Node 通过 state.event() 追加 AuditEvent 和 TraceEntry。
  • Trace 可更新，不是不可变快照；锁定的候选结果保持不可变。
  • 只有可审核候选时进入 REFERENCE_REVIEW_REQUIRED，不会追加虚假的 UNRESOLVED LinkAttempt。
  • 可解释数据库更新前后的召回、排除和排名变化。

POST-GRAPH GOVERNANCE

五、人工审批与锁定支线

Recommendation Ready / Reference Review → Approval → Lock

  • PRIMARY_RECOMMENDATION 可走标准审批。
  • USABLE_WITH_ASSUMPTIONS 必须显式接受假设。
  • REFERENCE_ONLY 仅在没有硬阻断时进入 REFERENCE_REVIEW_REQUIRED，只能使用带理由的 Reference Override。
  • Reference Review 是“已有可追溯值但需治理确认”，不会被 Trace 错记为所有策略耗尽。
  • UNADJUSTED_PROCESS_PROXY 进入 PROCESS_MODEL_REQUIRED，只保留在 Trace/诊断区，不进入 Recommendation。
  • Approve 与 Lock 都会重新检查硬门禁；存储层异常也不能让工艺诊断候选被锁定。
  • 草案、聚合和待审核目录来源封顶为 REFERENCE_ONLY，除非绑定受审 production_approval_id。
  • 正式模式默认禁用待审核 Profile、跨材料通用参数和生命周期包含假设；工程试算需显式开启。
  • 锁定后 Factor Resolution 不可变；重复锁定同一 Candidate 幂等，改锁其他 Candidate 拒绝。

为什么不画成 Graph Node

审批、拒绝和锁定由 A1FactorResolutionEngine Facade 与 ResolutionStorePort 执行。它们消费 Graph 的 Recommendation，但不参与因子检索和候选解析，因此保持为清晰的后处理治理边界。
